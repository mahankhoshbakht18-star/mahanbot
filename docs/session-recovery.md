# بازیابی نشست و مالکیت مرورگر

1. نتیجه navigation/reload از DOM واقعی دوباره تشخیص داده می‌شود.
2. اگر بانک باقی باشد، گزینه‌ها دوباره خوانده می‌شوند و احراز هویت اضافی انجام نمی‌شود.
3. اگر OTP دیده شود، همان `OTPWorkflowController` ورود اولیه اجرا می‌شود.
4. کد مصرف‌شده/منقضی از مسیر رسمی resend موجود، یا GET آدرس رسمی انتخاب بانک،
   جایگزین می‌شود؛ سپس مرحله واقعی دوباره تشخیص داده می‌شود.
5. فرم مرحله اول به‌خودی‌خود اثبات انقضای server-side نیست. اطلاعات متقاضی حفظ و
   ورود عادی انجام می‌شود. بدون ضرورت Cookieها پاک نمی‌شوند.

تلاش بازیابی محدود است (پیش‌فرض ۳)، با backoff قابل لغو ۰٫۵، ۱ و ۲ ثانیه.
رسیدن به حد، نیازمند اقدام کاربر است. resume صریح کاربر شمارنده را آزاد می‌کند.
ساعت OTP محلی، زمان انقضای نشست احرازشده صفحه سوم را تعیین نمی‌کند.

پایش نبود بانک از فاصله تنظیم‌شده و `bank_monitor_enabled` استفاده می‌کند. سند GET
با reload معمولی و سند POST با GET آدرس رسمی ورود انتخاب بانک بررسی می‌شود تا
بازارسال ناخواسته POST رخ ندهد. پایان reload تضمین تازه‌شدن ظرفیت سرور نیست.
هیچ unload/logout handler امنیتی در مسیر اصلاح‌شده خنثی نمی‌شود.

۴۰۳/۴۲۹، WAF و وضعیت مبهم، فرم را برای بررسی کاربر نگه می‌دارند. درخواست قبلی
با نتیجه نامشخص، قبل از reload یا احراز هویت جدید باید از مسیر رسمی بررسی شود.
چون endpoint رسمی استعلام نتیجه در دسترس این مأموریت نیست، سیستم آن را جعل نمی‌کند:
متوقف می‌شود و خودکار قفل را باز نمی‌کند.

هر متقاضی Context و مالک مستقل دارد. HTTP عملیات Playwright اجرا نمی‌کند؛ pause،
resume، redetect و تغییر شهر به صف مالک می‌روند. تعویض page از owner بازخوانی
می‌شود. listenerهای کنترلر قدیمی پس از خروج جدا می‌شوند. تب بسته‌شده checkpoint
را پاک نمی‌کند و تلاش مرورگر بعدی هم دوباره قفل ثبت نهایی را کنترل می‌کند.

قفل ثبت نهایی پیش از click با تراکنش SQLite گرفته می‌شود. خطای HTTP، timeout،
بسته‌شدن مرورگر یا پیام قدیمی ظرفیت، اجازه آزادکردن آن را نمی‌دهد. تنها پاسخ تازه
و قطعی رد ظرفیت یا تأیید نتیجه آن را تعیین تکلیف می‌کند. رزرو تأییدشده جداست.

HTML ذخیره‌شده نشست معتبر ایجاد نمی‌کند. فایل snapshot هرگز جایگزین شواهد زنده نیست.
registry مالکیت هنوز درون یک process است؛ برای چند worker مستقل باید قفل مالکیت
مرورگر در سطح سیستم/دیتابیس طراحی و جداگانه تست شود.
