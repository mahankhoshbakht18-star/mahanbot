# سند مرجع اصلی پروژه MahanBot

**تاریخ تثبیت مرجع:** ۲۰ ژوئیهٔ ۲۰۲۶  
**فایل مبنا:** `mahanbot13.zip`  
**SHA-256 فایل ورودی:** `dc542d0e46ee886beb46c2ed87abeb7ad83cd0faffab56ecc92db5d8a339227c`

این سند، خلاصهٔ تصمیم‌ها و وضعیت پروژه در گفتگوهای گذشته و نتیجهٔ بازبینی فایل مبنای فعلی است. از این نسخه به بعد، همین پوشه و همین سند مرجع ادامهٔ توسعه هستند.

---

## ۱. هدف پروژه

MahanBot یک سامانهٔ محلی ویندوز برای مدیریت نیمه‌خودکار فرایندهای ثبت‌نام، انتخاب بانک/شعبه، پیگیری وضعیت متقاضیان، دریافت و هماهنگی OTP، اجرای مرورگر و نمایش وضعیت عملیات در داشبورد است.

اهداف اصلی:

- اجرای یک‌کلیکی روی Windows
- مدیریت متقاضیان و داده‌های ثبت‌نام در SQLite
- اجرای گردش‌های Register، Select Bank و Status با Playwright
- دریافت و هماهنگی OTP بدون Polling سنگین
- نمایش زندهٔ لاگ و وضعیت با WebSocket
- اتصال کنترل‌شده به SMSForwardManager
- استفاده از مدل محلی کاربر در آزمایشگاه آفلاین
- حفظ قابلیت توقف، بازیابی، پشتیبان‌گیری و Rollback

## ۲. معماری فعلی

### هستهٔ سرور و اجرا

- `unified_launcher.py`: اجرای یک‌کلیکی، ساخت محیط، مدیریت فایل تنظیمات و پشتیبان دیتابیس
- `unified_server.py`: اجرای هم‌زمان داشبورد محلی و سرویس ورودی پیامک
- `server.py`: API اصلی FastAPI، مدیریت Jobها، متقاضیان، تنظیمات، OTP و WebSocket
- `database.py`: دسترسی SQLite، تنظیمات و اطلاعات متقاضیان
- `event_logger.py`: ثبت و انتشار رخدادها با پاک‌سازی بخشی از داده‌های حساس

### اتوماسیون مرورگر

- `bot_core.py`: امکانات مشترک Botها، مرورگر، OTP، Watchdog و Recovery
- `bot_register.py`: جریان ثبت‌نام
- `bot_select.py`: جریان انتخاب بانک/شعبه و OTP
- `bot_status.py`: استعلام و وضعیت پرونده
- `browser_launcher.py`: ساخت Browser Context، Allowlist و ناوبری کنترل‌شده
- `browser_actions.py`: لایهٔ مشترک ورود متن، Select و Click

### کپچا و مدل محلی

- `captcha_service.py`: مرز مرکزی سرویس کپچا
- `offline_model_lab.py`: بارگذاری و اجرای مدل محلی آفلاین
- `model_lab_api.py`: API آزمایشگاه مدل در داشبورد
- `requirements-model.txt`: وابستگی‌های Torch/Pillow

مدل `my_captcha_model.pth` داخل فایل مبنا نیست. مسیر استاندارد آن ریشهٔ پروژه، کنار `captcha_service.py` و `unified_server.py` است؛ مسیر جایگزین از `MAHANBOT_CAPTCHA_MODEL_PATH` خوانده می‌شود.

### پیامک و Android Bridge

- `server_sms_bridge.py`: وضعیت دستگاه، اعلان رسیدن پیامک و اطلاعات راه‌اندازی
- `sms_ingress.py`: سرویس جداگانه روی پورت پیش‌فرض 8010
- `sms_notify_core.py`: Registry اعلان‌ها و Heartbeat دستگاه
- `android_bridge/`: کلاس‌های Kotlin برای اتصال SMSForwardManager

**وضعیت فعلی:** Android Bridge فقط رسیدن پیامک را اعلام می‌کند و متن پیام یا OTP را منتقل نمی‌کند. در مقابل، API اصلی MahanBot مسیرهای `/receive_sms` و `/manual_otp` را برای دریافت واقعی کد دارد. اتصال این دو بخش هنوز کامل نشده است.

### رابط کاربری

- `static/index.html` و `static/script.js`: داشبورد اصلی و تنظیمات
- `ui_v2.py`، `static/ui_v2.css` و `static/ui_v2.js`: پوستهٔ مدرن
- `static/model_lab.*`: رابط آزمایشگاه مدل
- `static/sms_notify_bridge.js`: وضعیت اتصال گوشی

## ۳. تاریخچهٔ تصمیم‌ها و فازهای قبلی

### فاز Audit و پاک‌سازی اولیه

- ایجاد لایهٔ مشترک `BrowserActions`
- بررسی visible/enabled/editable پیش از تغییر فیلد
- استفاده از Ctrl+A و Backspace، ورود مقدار و کنترل `input_value`
- جلوگیری از تغییر فیلدهای hidden/read-only
- پارامتری‌کردن JavaScript برای کاهش تزریق ناخواسته
- اضافه‌شدن تست‌های پایه و `scripts/quality_check.py`

### فاز کارایی و هم‌زمانی

- محدودکردن Worker Pool و جلوگیری از هم‌زمانی نامحدود
- کاهش مقدار عملیاتی concurrency و ایجاد سقف محافظ
- بهبود تنظیمات SQLite با WAL، busy timeout و اتصال‌های کوتاه‌عمر
- بهبود API solver با timeout و pooling
- اشتراک منابع مدل و OCR میان Workerها به‌جای بارگذاری تکراری

### فاز OTP

- ایجاد مسیرهای `/wait_otp/{nid}`، `/receive_sms` و `/manual_otp`
- استفاده از Event برای بیدارکردن Waiterها
- ذخیرهٔ timestamp برای OTP
- تلاش برای حل Race میان ذخیره در DB و Signal

### فاز Windows One-Click

- ساخت `START_MAHANBOT.cmd`
- ساخت و مدیریت venv
- تنظیم پورت‌های 8000 و 8010
- پشتیبان‌گیری SQLite پیش از اجرا
- رفع مشکل `WinError 32` ناشی از بازبودن اتصال SQLite هنگام Backup/Rename
- ثبت مشکل محیطی `WinError 206` هنگام نصب Torch در مسیرهای بسیار طولانی؛ مسیر کوتاه مانند `C:\MahanBot` پیشنهاد عملیاتی است

### فاز رابط کاربری

- طراحی آبی، فیروزه‌ای، نیلی، طلایی و نارنجی
- سایدبار، کارت‌های آماری، ترمینال سبک‌تر و نمایش بهتر موبایل
- محدودسازی تعداد ردیف‌های لاگ در DOM
- استفاده از WebSocket به‌عنوان مسیر اصلی و Polling به‌عنوان fallback

### فاز مدل محلی

- پشتیبانی از مسیر مستقیم مدل و متغیر محیطی
- پشتیبانی از checkpointهای `state_dict`، `model_state_dict` و `model`
- حذف prefixهای رایج مانند `module.`، `_orig_mod.` و `model.`
- بارگذاری CPU/GPU بر اساس تنظیم دستگاه
- اعتبارسنجی تصویر و خروجی مدل
- ایجاد آزمایشگاه آفلاین برای بررسی اپراتور

## ۴. محدودیت‌ها و تصمیم‌های ثابت پروژه

این موارد بدون تصمیم فنی جدید نباید تغییر کنند:

1. منطق اصلی OTP و مسیرهای ناوبری فقط با تست و دلیل مشخص تغییر کند.
2. صفحهٔ واسط قدیمی مرورگر و تمام ارجاع‌های اجرایی آن حذف‌شده باقی بمانند.
3. `final_submit=false` به‌صورت پیش‌فرض حفظ شود تا ربات در مرحلهٔ نهایی بدون اجازهٔ کاربر ثبت قطعی نکند.
4. فایل مدل بزرگ داخل ZIP اجباری نیست و کاربر آن را در ریشهٔ پروژه قرار می‌دهد.
5. تغییرات باید روی فایل واقعی پروژه اعمال، تست و مجدداً بسته‌بندی شوند.
6. پشتیبان‌گیری و امکان Rollback قبل از تغییرات حساس حفظ شود.
7. مدل محلی فعلی در مسیر آفلاین/آزمایشگاهی قرار دارد و خروجی آن به‌صورت خودکار به گردش زندهٔ مرورگر تزریق نمی‌شود.

## ۵. اصلاحات اعمال‌شده روی نسخهٔ مبنا در این بازبینی

### ۵.۱ جداسازی «سرعت ورود اطلاعات» از «حالت کپچا»

در نسخهٔ ورودی، گزینهٔ ظاهری «انسانی/سریع» به `captcha_mode` وصل بود و سرعت تایپ فیلدها را کنترل نمی‌کرد. این اشتباه معماری اصلاح شد.

تنظیمات جدید:

- `interaction_mode=human|fast`
- `human_typing_delay_ms=70`
- `fast_typing_delay_ms=0`

رفتارها:

- **Human:** کلیک، Ctrl+A، Backspace، تایپ کاراکتر‌به‌کاراکتر، کنترل مقدار نهایی و خروج از فیلد
- **Fast:** کلیک، Ctrl+A، Backspace، `fill()` فوری، کنترل مقدار نهایی و خروج از فیلد

هر دو حالت visible/enabled/editable بودن فیلد را بررسی می‌کنند و مقدار نهایی را با `input_value()` می‌سنجند.

این تنظیم اکنون روی مسیرهای اصلی ورود متن اعمال می‌شود، از جمله:

- کد ملی
- کد OTP
- سال تولد و سال ازدواج
- کد رهگیری
- ورودی‌های متنی ثبت‌نام
- ورودی‌های متنی جریان انتخاب بانک
- ورودی‌های متنی استعلام وضعیت

### ۵.۲ اصلاح مسیر دیتابیس

`database.py` اکنون واقعاً از `MAHANBOT_DB_PATH` استفاده می‌کند. پیش از این، فایل env مسیر دیتابیس را تعیین می‌کرد ولی لایهٔ دیتابیس همیشه فایل کنار کد را باز می‌کرد.

### ۵.۳ حذف کامل صفحهٔ واسط قدیمی

- تابع و ثابت‌های مربوط از `browser_launcher.py` حذف شدند
- فراخوانی‌ها از Botها حذف شدند
- Monkey Patch مربوط از `unified_server.py` حذف شد
- Cleanup ظاهری قدیمی از CSS/JS حذف شد

### ۵.۴ حفظ پیاده‌سازی اصلی کپچا

طبق تصمیم مالک پروژه، بخش کپچا خارج از محدودهٔ بازطراحی این نسخه است. فایل `captcha_service.py` عیناً از ZIP اولیهٔ `mahanbot13.zip` بازگردانی شده و رفتار مدل محلی آن بدون تغییر حفظ شده است. تغییر حالت ورود فیلدها مستقل از کپچا است.

### ۵.۵ وضعیت تست

- `compileall`: موفق
- Unit Test: ۴۴ تست موفق
- ۳ تست یکپارچه به‌علت نصب نبودن مجموعهٔ کامل وابستگی‌های Unified Server در محیط بررسی Skip شدند

## ۶. نقاط ضعف فعلی و اولویت ارتقا

### P0 — امنیت و صحت عملیات

1. **API Key به‌صورت Fail-Open است.** وقتی `MAHANBOT_API_KEY` خالی باشد، API اجازهٔ دسترسی می‌دهد و Launcher نیز آن را خالی می‌نویسد.
2. **CORS در `server.py` روی `*` است.** Unified Server محافظ Origin دارد، اما اجرای مستقیم Legacy Server همچنان بازتر از حد لازم است.
3. **OTP و پیش‌بینی‌های کپچا به‌صورت متن ساده در SQLite نگه‌داری می‌شوند.** Retention و رمزگذاری وجود ندارد.
4. **برخی لاگ‌های Bot هنوز مقدار OTP را مستقیماً در متن ثبت می‌کنند.** پاک‌سازی مرکزی همهٔ مسیرهای مستقیم را پوشش نمی‌دهد.
5. **تازگی OTP در همهٔ مسیرها یکسان اعمال نشده است.** `fetch_otp_fast()` هنوز `min_ts` را نادیده می‌گیرد و بعضی مسیرها مستقیماً DB را می‌خوانند؛ خطر مصرف OTP قدیمی یا استفادهٔ مجدد وجود دارد.
6. **بخش کپچا در این نسخه ارزیابی یا بازطراحی نشده است.** رفتار آن مطابق ZIP اولیه حفظ شده و هرگونه تست، اصلاح یا بهینه‌سازی آن باید در یک مسیر تخصصی مستقل انجام شود.
7. **`retry_count=1000` عملاً Jobهای بسیار طولانی می‌سازد.** باید Backoff، سقف تلاش هر مرحله و Circuit Breaker اضافه شود.
8. **فایل `mahanbot.env` شامل کلید دستگاه است.** این فایل نباید در نسخهٔ عمومی، Git یا ZIP قابل انتشار قرار گیرد و کلید فعلی باید پس از هر انتشار ناخواسته Rotate شود.

### P1 — پایداری و نگهداری

1. حدود **۲۴۲ بلوک `except Exception`** و **۱۱۰ مورد `pass`** در کد اجرایی وجود دارد؛ بسیاری از خطاها بدون context پنهان می‌شوند.
2. منطق Selector، Recovery، Captcha و انتظار در `bot_register.py` و `bot_select.py` تکرار شده است.
3. URL سرویس Remote OTP در `bot_core.py` ثابت و Hardcoded است.
4. Schema Migration نسخه‌بندی‌شده وجود ندارد؛ تغییر ساختار DB به روش `CREATE TABLE IF NOT EXISTS` محدود شده است.
5. وضعیت‌ها میان فارسی و انگلیسی یکدست نیستند و State Machine رسمی ندارند.
6. فایل‌های requirements بازهٔ نسخه دارند ولی Lockfile و Hash دقیق ندارند؛ Build در آینده ممکن است متفاوت شود.
7. تست واقعی Chromium/Edge، Torch و مدل در محیط بررسی انجام نشده است.
8. سه تست Unified Server بدون وابستگی کامل Skip می‌شوند و باید در CI ویندوز اجباری شوند.
9. رابط اصلی هنوز برای Bootstrap و Font Awesome به CDN وابسته است و در حالت کاملاً آفلاین ظاهر ناقص می‌شود.
10. پوشهٔ پروژه شامل Backupهای متعدد DB، Screenshot، Chrome Profile و `__pycache__` است؛ Release و Runtime Data باید از Source جدا شوند.

### P2 — توسعهٔ محصول

1. SMSForwardManager فقط اعلان رسیدن پیامک می‌فرستد و اتصال واقعی OTP/NID هنوز نهایی نشده است.
2. داشبورد مدیریت Secret، Rotation کلید و وضعیت اعتبارسنجی دستگاه ندارد.
3. Metrics عملیاتی برای نرخ موفقیت هر مرحله، زمان OTP، تعداد Retry و خطاهای Selector وجود ندارد.
4. Page Objectهای مجزا برای صفحات سامانه ایجاد نشده‌اند.
5. مکانیزم Update/Version Manifest و Migration خودکار نسخهٔ ویندوز وجود ندارد.
6. Backup Retention، Export/Import و Restore Wizard در UI وجود ندارد.

## به‌روزرسانی ۲۰ ژوئیه ۲۰۲۶: اتصال SMSForwardManager 2.5.0

- اپ مدیریت پیامک اکنون کد ملی متقاضی فعال، نشانی MahanBot، کلید دستگاه و عبارت شناسایی پیامک دارد.

- OTP پس از موفقیت مصرف و مقدار آن حذف می‌شود.
- حالت `human/fast` روی فیلد OTP نیز اعمال می‌شود.
- متن کامل پیامک و شماره فرستنده به MahanBot ارسال نمی‌شود.
- فایل `captcha_service.py` در این فاز بدون تغییر باقی مانده است.
